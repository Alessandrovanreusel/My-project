## Story

As a player,
I want a drunk NPC to stumble out of the pub, sway, nearly fall, and wander off,
so that I have a real, telegraphed moment to try to catch.

## Acceptance Criteria

**AC1 — Husband Animator drives the lifecycle phases (AR10, FR11)**
- An **Animator Controller for the drunk** is built from the **Male Drunk Pack** clips so that the husband model visibly animates as the `EventActor` advances phases.
- The controller has **named states** the engine `CrossFade`s into — at minimum an **idle**, an **idle-variation** (the peak stagger/near-fall/slump), a **walk**, a **turn**, and a **run** are available (AR10). Each phase's `animStateName` in the `TownDrunk` EventDefinition maps **exactly** to one of these state names.
- Driving is **state-name CrossFade only** (the engine's existing mechanism) — **no `Speed` parameter, no `CharacterAnimator` component** on the drunk. (The player's `CharacterAnimator.controller` / `CharacterAnimator.cs` are NOT reused here.)

**AC2 — TownDrunk runs the full pub→peak→alley lifecycle on the engine + baked NavMesh (FR11)**
- A **`TownDrunk` EventDefinition** asset runs on the Story 1.6 engine: the drunk **spawns** (leaving the pub), **stumble-walks a route** along the baked NavMesh, hits a **peak stagger/near-fall** with a **~1.5 s money-shot window**, **recovers and keeps walking**, then **despawns into an alley** — over a **~20–30 s** total lifecycle.
- The drunk **physically moves** along a route via its `NavMeshAgent` during the walking phases and **stops in place** during the peak (so it's a stationary, framable "money shot").
- **One** drunk is active at a time (`maxConcurrent = 1`, NFR6), drawn from the pool (no `Instantiate`/`Destroy` in the loop, NFR3), and the cycle **repeats** after the manager's respawn delay with **no object leaks** (one pooled instance reused).

**AC3 — Peak fires the EventPeakedChannel; everything is fail-soft (FR11 hook, NFR8, NFR5)**
- On **entering Peak**, the actor raises **`EventPeakedChannel`** (the seam grading in 1.9–1.10 and future audio in 1.8 will hook).
- **NavMesh is fail-soft (the owed `isOnNavMesh` guard):** if the actor **was given a real route** but the agent can't use the NavMesh (off-mesh or disabled), it **logs one clear warning per spawn and the timer FSM still runs to completion** — it never throws into `Update`. A **missing/empty route is not a misconfiguration**: it is a valid stand-still lifecycle and is accepted **silently, with no warning** (`EventManager.route` is optional by design — see `EventRoute`'s "null or empty waypoint list is valid" and the manager's "Null = the actor runs its lifecycle in place"). Animation remains independently fail-soft (a missing controller/state never throws).
  - *(AC text amended by code review 2026-07-16: the original wording also demanded a warning when "the route is missing/empty", which contradicted Task 3's predicate that the code correctly implements. The design intent — an optional route — wins; the AC now matches it.)*
- After every script change, **MCP `read_console` shows zero errors and zero new warnings** (NFR5); URP untouched (NFR4); no regressions to Move/Look/Sprint/Jump or the 1.3–1.5 raise/zoom/capture flow.
